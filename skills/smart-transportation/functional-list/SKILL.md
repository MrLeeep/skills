# 智慧交通功能清单生成

不要把需求原文简单复制到 Excel。目标是把需求拆到能够开发、联调和验收的粒度。

## 拆解层级

业务域 → 一级模块 → 二级模块 → 三级功能 → 业务场景 → 功能逻辑

## 每项功能至少包含

- 功能编号
- 一级模块
- 二级模块
- 三级功能
- 功能名称
- 需求来源
- 业务场景
- 用户角色
- 触发条件
- 前置条件
- 输入
- 数据来源
- 处理逻辑
- 业务规则
- 算法依赖
- AI 智能体依赖
- 知识库/RAG/知识图谱依赖
- 接口依赖
- 设备依赖
- 输出
- 页面交互
- 审核机制
- 异常处理
- 执行反馈
- 验收标准
- 优先级
- 当前状态
- Owner
- 待确认问题

## 粒度判断

一条功能只有在以下角色都能理解时才算拆解完成：

- 产品知道页面和交互怎么设计
- 后端知道输入、处理和接口
- 算法知道输入输出和指标
- Agent 研发知道工具、规则和边界
- 测试知道怎么写测试用例
- 项目经理知道依赖、Owner 和风险
- 甲方知道最终会交付什么

## 智慧隧道建议业务域

- 应急处置 / 预案自动生成
- 数字问数 / 数据服务
- 运营管理综合研判
- 设备运维
- 能耗管理
- 通行效率
- 安全风险
- 供配电保障
- 隧道机电联动

不要自行添加项目材料没有提出的功能；行业通用但材料未确认的内容标记为“建议需求”。

## 验收标准写法

禁止写“功能正常”“满足需求”等不可测试表述。优先写成：

给定前置条件 + 输入/操作 + 系统行为 + 期望结果 + 可验证证据。

## 输出

默认输出表格；如果用户要 Excel，则按上述字段生成可直接用于研发排期和项目跟踪的结构。最后单独列出待确认问题和高风险依赖。
