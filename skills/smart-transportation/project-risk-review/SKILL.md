# 智慧交通项目风险审查

目标不是罗列泛化风险，而是识别会影响开发、联调、上线和验收的具体问题，并给出 Owner、影响和下一动作。

## 风险分类

### 需求风险
- 需求未冻结
- 业务规则不清楚
- 功能边界不清楚
- 需求来源冲突
- 验收口径缺失

### 数据风险
- 数据未提供
- 字段未知
- 数据质量未知
- 历史数据不足
- 实时性不满足
- 第三方提供时间未知

### 接口风险
- API 未提供
- 接口文档不完整
- 测试环境不存在
- 鉴权/网络未打通
- 返回状态不足以确认业务结果

### 算法风险
- 模型未开发
- 样本不足
- 输入数据未就绪
- 准确率指标未定义
- 算法结果与业务规则边界不清

### AI 智能体风险
- 输出格式不稳定
- 幻觉导致事实错误
- Tool 调用失败
- 数据依据不可追溯
- 能力边界被夸大
- 高风险操作缺少人工确认

### 设备风险
- 协议未知
- 设备不可控
- 无状态反馈
- 点位/台账不准确
- 缺少真实测试环境
- API 成功但无法证明设备执行成功

### 项目风险
- 第三方依赖
- 研发资源不足
- 联调窗口过短
- 验收日期固定但前置条件未满足
- 交付成果定义不清
- 源码/环境/部署责任存在争议

## 风险分级

高：已经或极可能阻塞关键路径、验收或上线。
中：不立即阻塞，但会影响范围、质量、排期或联调。
低：可通过常规项目管理消化。

## 每条风险必须包含

风险编号｜类别｜风险描述｜触发条件｜当前证据｜影响模块｜影响范围｜风险等级｜责任方｜Owner｜建议动作｜最晚解决时间｜当前状态｜是否阻塞里程碑

不要在没有依据时虚构概率或日期。

## 关键路径检查

重点检查：

需求冻结 → 数据准备 → 接口准备 → 算法/Agent 开发 → 平台集成 → 第三方联调 → 设备联调 → 测试 → 验收

如果固定验收日期早于关键依赖的预计完成时间，明确指出“计划倒挂”。

## 输出

1. 项目总体风险判断
2. Top 风险
3. 完整风险清单
4. 当前阻塞项
5. 需要领导/甲方协调事项
6. 本周建议动作
7. 对里程碑和验收的影响

面向领导汇报时使用事实、影响、需要协调的事项和下一步，不堆砌技术细节。
